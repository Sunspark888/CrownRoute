# C1 监督构建与代码来源

输入是一张 RGB 图块及其树冠弱框。FastSAM-s 对每张图块推理一次，各弱框共享候选池并独立选择候选。输出以一个弱框对应一条训练记录组织。项目脚本通过 OpenCV 解码，以 BGR 通道顺序进行颜色计算。

| 论文流程 | 原项目依据 | 本仓库实现 |
| --- | --- | --- |
| 候选池、关联、路径 I 细化 | `step10_2_fastsam_refiner_full.py` 的 `main`、`get_candidate_masks_from_fastsam`、`choose_best_mask_with_multiscore`、`refine_mask_first_version` | `crownroute/association.py` 保存原始计算函数。`pipeline.generate_candidates` 使用冻结的推理参数。 |
| 路径 I 优先，然后判断路径 II 资格 | `step10_3_classify_instances_full.py::classify_instance`。上游 `step10_2` 保存的特征不含 `gt_coverage` 和 `area_score`，两个备用条件不会触发。 | `crownroute/eligibility.py` 为原判断函数。`pipeline.construct_record` 仅传递实际关联特征。 |
| 路径 II 重建 | `step10_5_hole_recovery_full.py` 中的 `build_initial_mask`、`contrast_aware_hole_recovery` 和图块坐标回填 | `crownroute/reconstruction.py` 从弱框内 RGB 重建，使用纹理与绿色区域的交集、形态学处理和局部洞恢复。 |
| 取用两条路径的掩码，共享规范化 | `step10_6_build_final_dataset_full.py` 为 A 取 refined mask，为 B 取 after-hole-recovery mask。`step10_8_build_final_dataset_v2_ab_holefill.py` 对两条路径调用 `step10_7_ab_holefill_preview_300.py::repair_mask`。 | `crownroute/normalization.py` 保存原始规范化函数。`pipeline.construct_record` 在对应路径调用。 |
| 固定接纳、标准监督组装 | `build_proposed_final_variants_20260628.py::enrich/frozen_rules/materialize`、`frozen_rule_manifest.json`、`proposed_v3_balanced/split/train.txt` 和对应的 `meta/dataset_records.json` | `pipeline.admission_score`、`configs/c1.json` 和 `scripts/build_supervision.py`。先收全部 A，再按原关联特征接纳合格 B。 |

路径 I 的可靠条件为 s ≥ 0.75、u ≥ 0.60、r ≥ 0.75。其余候选在 0.45 ≤ s < 0.80 且 g ≥ 0.50 时具有路径 II 资格。只在路径 II 使用接纳分数 q = 0.40s + 0.30u + 0.20r + 0.10g，冻结门限为 0.5401658842336331。其中 s、u、r、g 均取自原候选的关联步骤。A 的细化掩码和接纳后的 B 重建掩码进入标准训练集。历史代码也记录重建无法形成连通分量时的 `no_mask`，没有输出训练文件。对自备输入出现此情况时，接口单列 `unconstructed`，便于区分工程缺失和一次真实的接纳拒绝。

正式组装报告记录全部 3,718 条路径 II 资格记录均已有重建掩码，因而没有额外的空重建类别计入论文统计。门限来自 80% 的全局覆盖工作点和验证集可重建候选的关联分数分布。全局库存包括测试分组的路由类别计数。代码默认使用已冻结值。历史库存、训练图像、候选掩码和人工评价数据均由研究方管理。

## 在自备数据上运行

从仓库根目录执行。CPU 构建需 Python 3.10 或更高版本、NumPy 和 OpenCV。运行 FastSAM-s 另需安装 ultralytics、其 PyTorch 依赖并自行取得授权的权重。合成演示可以只使用前两项计算依赖。

```bash
python -m scripts.make_c1_demo demo_inputs
python -m scripts.build_supervision --manifest demo_inputs/patches.json --output demo_standard
python -m unittest discover -s tests -p "test_c1.py" -v
```

合成演示产生五个几何图案案例，依次为 A、B、门限拒绝、无重建资格、无有效候选。候选掩码列表用来独立演示下游实现。自备图像的完整推理命令为

```bash
python -m scripts.build_supervision --manifest input/patches.json --output standard --weights /path/to/FastSAM-s.pt --device cpu
```

例如，`input/patches.json` 可组织为

```json
{"patches": [{"id":"sample","image":"sample.png","split":"train","source_id":"source_1","boxes":[[20,20,76,76]]}]}
```

输入清单逐图块给出来源分区和左闭右开的整数坐标框。图像与输入掩码路径相对清单所在目录解析。同一来源使用同一分区。使用已保存候选时，在每个图块中加入按原顺序排列的 `candidate_masks` 路径列表，使用原尺寸二值 PNG 并省略权重参数。提供给 FastSAM 的输入为图像本身。

标准集写出 `meta/dataset_records.json`、`split/train.txt`、`split/val.txt`、`split/test.txt`、图像及单实例掩码。记录内路径相对数据集根目录。全部路由另存于 `meta/route_outcomes.json`。多个框共享同一个图像文件且分别保留实例记录。历史运行在路由前为匹配候选计算过细化中间件，本仓库仅为实际走路径 I 的记录计算该中间件。

## 已核对的范围

- 正式训练成员清单含 6,857 个唯一 ID。对应元数据中 4,778 条为 A，2,079 条为 B。上述 B 全部满足冻结接纳门限。
- 按正式训练清单顺序，分别取 A 和 B 的前四条记录，从历史保存的关联候选重放。八条记录的关联特征、路由及最终掩码均与正式文件一致，每张掩码的像素差异均为零。这一检查从已选候选开始。
- 在纯合成图块上实跑一次 FastSAM-s CPU 推理，同一候选池处理两个弱框，得到两条门限拒绝记录。合成候选演示另覆盖 A、B、直接拒绝与接纳拒绝。轻量检查环境为 Python 3.12.14、NumPy 2.4.4、OpenCV 4.13.0、ultralytics 8.4.75。
- 本目录提取作者项目中用于上述计算的函数，新增可移植的输入输出接口。第三方软件以依赖引用，此处没有随附第三方权重或研究图像。
